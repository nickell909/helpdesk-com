# Диаграмма Питера Чена для системы Helpdesk

## 📋 Содержание

В папке `/docs` находятся следующие файлы с диаграммой в нотации Питера Чена:

1. **chen-diagram-description.md** — Полное текстовое описание диаграммы с пояснениями
2. **chen-diagram-ascii.txt** — ASCII-версия диаграммы для быстрого просмотра в текстовом редакторе
3. **chen-diagram-drawio.xml** — Файл для импорта в draw.io (diagrams.net)

---

## 🎨 Как использовать

### Вариант 1: Просмотр текстового описания

Откройте файл `chen-diagram-description.md` в любом редакторе Markdown:

```bash
cat docs/chen-diagram-description.md
```

Или откройте в GitHub для красивого отображения.

### Вариант 2: Просмотр ASCII-версии

Откройте файл `chen-diagram-ascii.txt` в текстовом редакторе:

```bash
cat docs/chen-diagram-ascii.txt
# или
less docs/chen-diagram-ascii.txt
# или
nano docs/chen-diagram-ascii.txt
```

### Вариант 3: Визуализация в draw.io

1. Перейдите на сайт [diagrams.net](https://app.diagrams.net/) (ранее draw.io)
2. Нажмите **File → Open from → Device**
3. Выберите файл `chen-diagram-drawio.xml`
4. Диаграмма откроется с готовой структурой
5. При необходимости отредактируйте элементы и сохраните

**Примечание**: Файл XML содержит структуру, но линии связей нужно будет дорисовать вручную для точного расположения.

### Вариант 4: Создание диаграммы в других инструментах

Используйте текстовое описание из `chen-diagram-description.md` как руководство для построения диаграммы в:

- **Lucidchart** — https://www.lucidchart.com/
- **Microsoft Visio** — для Windows
- **yEd Graph Editor** — https://www.yworks.com/products/yed
- **Creately** — https://creately.com/
- **ERDPlus** — https://erdplus.com/

## 📐 Структура диаграммы

### Сущности (Entities) — 8 шт:

1. **Пользователь** (User)
2. **Роль** (Role)
3. **Заявка** (Ticket) — центральная сущность
4. **Категория** (Category)
5. **Приоритет** (Priority)
6. **Статус** (Status)
7. **Комментарий** (Comment)
8. **История заявки** (TicketHistory)

### Связи (Relationships) — 10 шт:

1. Пользователь ←→ Роль (N:1)
2. Заявка ←→ Пользователь — создатель (N:1)
3. Заявка ←→ Пользователь — исполнитель (N:1)
4. Заявка ←→ Категория (N:1)
5. Заявка ←→ Приоритет (N:1)
6. Заявка ←→ Статус (N:1)
7. Комментарий ←→ Заявка (N:1)
8. Комментарий ←→ Пользователь (N:1)
9. История ←→ Заявка (N:1)
10. История ←→ Пользователь (N:1)

## 🔑 Обозначения нотации Питера Чена

| Элемент | Обозначение | Описание |
|---------|-------------|----------|
| Сущность | Прямоугольник | Объект предметной области |
| Атрибут | Овал | Свойство сущности |
| Ключевой атрибут | Овал с подчеркиванием | Первичный ключ (Primary Key) |
| Связь | Ромб | Отношение между сущностями |
| Линия | Прямая линия | Соединяет элементы |
| Кардинальность | 1, N, M | Множественность связи |

### Типы кардинальности:

- **1:1** — Один к одному
- **1:N** — Один ко многим
- **M:N** — Многие ко многим (в данном проекте не используется)

### Обозначение участия:

- **(1, 1)** — Обязательное участие ровно одного
- **(0, 1)** — Необязательное участие не более одного
- **(0, N)** — Необязательное участие многих
- **(1, N)** — Обязательное участие хотя бы одного из многих

## 📊 Пример связи на диаграмме

```
┌─────────────┐                         ┌─────────────┐
│ Пользователь│                         │    Роль     │
└──────┬──────┘                         └──────┬──────┘
       │                                       │
       │ N                                     │ 1
       │                                       │
       └───────────────┐       ┏───────────────┘
                       │       │
                      ┌┴───────┴┐
                      │  имеет  │
                      │  роль   │
                      └─────────┘
```

**Интерпретация**: Много (N) пользователей может иметь одну (1) роль. Роль может быть назначена многим пользователям.

## 🎯 Рекомендации по построению

### Расположение элементов:

1. **Центр**: Заявка — центральная сущность системы
2. **Вверху**: Пользователь и Роль
3. **Слева**: Категория
4. **Справа**: Приоритет
5. **Справа внизу**: Статус
6. **Внизу слева**: Комментарий
7. **Внизу справа**: История

### Порядок построения:

1. Нарисуйте все прямоугольники (сущности)
2. Для каждой сущности добавьте овалы (атрибуты)
3. Подчеркните первичные ключи
4. Нарисуйте ромбы (связи) между сущностями
5. Соедините линиями сущности с ромбами
6. Подпишите кардинальность около линий
7. Добавьте названия связей внутри ромбов

## 📝 Что отображает диаграмма

Диаграмма в нотации Питера Чена показывает:

✅ **Концептуальную модель данных** системы Helpdesk
✅ **Все сущности** и их атрибуты
✅ **Связи между сущностями** и их типы
✅ **Кардинальность связей** (один-к-одному, один-ко-многим)
✅ **Первичные ключи** (подчеркнутые атрибуты)
✅ **Семантику связей** (имеет роль, создана пользователем и т.д.)

❌ Диаграмма НЕ показывает:

- Внешние ключи (они представлены связями)
- Индексы базы данных
- Ограничения (constraints)
- Триггеры и хранимые процедуры
- Физическую реализацию

Для физической структуры БД смотрите SQL DDL скрипты в папке `/docs`.

## 🔗 Связь с реализацией

Диаграмма соответствует:

- **Java-сущностям** в `/src/main/java/com/helpdesk/entity/`
- **Таблицам PostgreSQL** в базе данных `helpdesk_db`
- **SQL DDL скриптам** для создания таблиц

### Пример соответствия:

**Диаграмма Чена:**
```
┌──────────┐
│ Заявка   │
│          │
│ ticket_id│ ← ключевой атрибут
│ title    │ ← обычный атрибут
└──────────┘
```

**Java-сущность:**
```java
@Entity
@Table(name = "tickets")
public class Ticket {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long ticketId;  // ← ключевой атрибут

    private String title;    // ← обычный атрибут
}
```

**SQL таблица:**
```sql
CREATE TABLE tickets (
    ticket_id BIGSERIAL PRIMARY KEY,  -- ключевой атрибут
    title VARCHAR(200) NOT NULL       -- обычный атрибут
);
```
